# 全项目注释计划

> 目标：为 **in-scope 源码文件**（约 125 个）添加结构化文件头注释，并在关键逻辑处补充块/行注释，形成可维护的「代码地图」。
> 原则：**以真实代码为准**；`docs-site/` 与 `docs/` 为参考；文件头注释是代码内地图，**不替代**架构文档。
> 冲突处理：**默认只改注释**；若必须改代码才能消除矛盾，先列出问题并等待人工批准后再改。

---

## 1. 任务定义

### 1.1 不是什么

- ❌ 每个文件顶部只写一行 `// utils` 或 `@file xxx`（Docker 除外见 2.2）
- ❌ 用统一模板脚本批量生成注释
- ❌ 未读文件就写注释
- ❌ 未经批准改动业务逻辑
- ❌ 注释自解释的 import、变量名、框架 boilerplate
- ❌ 在 `i18n/*/index.ts` 里给每个翻译 key 加行内注释
- ❌ 在注释里复制整章 docs-site 内容

### 1.2 是什么

| 层级         | 要求                                                            |
| ------------ | --------------------------------------------------------------- |
| **文件头**   | 六字段结构化块（见第 2 节）；页面类可保留 UI/流程段落（见 2.3） |
| **关键逻辑** | 非显而易见分支、边界、与 config/文档的对应关系                  |
| **语言**     | 中文为主；技术术语保留英文（SSR、CSR、Bearer、hreflang 等）     |

## 2. 文件头注释模板

### 2.1 六字段模板（缺一不可）

**TypeScript / JavaScript**（`config/`、`app/**/*.ts` 等）：文件最顶部使用 `/* ... */` 块注释。

**Vue SFC**（`*.vue`）：块注释放在 **`<script setup>` 之上**（文件最顶部），使用 `<!-- ... -->`，与现有 13 个 page 一致。

**SCSS**：文件最顶部使用 `/* ... */`。

**Docker / Nginx / Compose**：文件最顶部使用 `#` 行注释，必须包含「文件职责」并展开 2～5 句（现有 `docker/*` 两行 `# 文件职责` 风格可保留并补全六字段要点）。

```txt
【文件职责】
  一句话摘要 + 2～5 句展开。

【架构位置】
  公开 SEO 区 / 登录产品区 / 共享层 / config / server / i18n / tests / docker 中的哪一层。

【主要导出 / 路由】
  组件名、函数名、常量、或 URL（如 /workspace、/docs/:id）。

【依赖关系】
  - 依赖：config/*、composable、store、API client 等
  - 被引用：1～3 个典型调用方

【渲染 / 数据】（page / middleware / server 路由必填；纯 config/util 可写「无」）
  - layout / middleware / SSR | prerender | SWR | CSR
  - 数据来源：public / auth / product API 或本地 config

【边界与注意】
  noindex、语言中性 URL、401 单飞、不可跨 feature 深引等。
```

**验收**：六字段齐全；**不以行数凑数**（小文件不必硬凑 8 行）。

### 2.2 按文件类型的补充要求

| 类型                       | 文件头额外说明                                              |
| -------------------------- | ----------------------------------------------------------- |
| `config/*.ts`              | 单一来源；被谁消费；修改需同步哪些 `tests/unit/*`           |
| `app/pages/*.vue`          | 见 2.3 页面合并模板                                         |
| `app/layouts/*.vue`        | 哪种 shell 包裹、哪些路由在用                               |
| `app/components/**/*.vue`  | 公开 / 产品 / 通用；是否 auto-import（`pathPrefix: false`） |
| `app/features/*/api.ts`    | adapter **相对路径**、client 类型、401 行为                 |
| `app/middleware/*.ts`      | 全局 vs 命名；执行顺序；301/404 决策树                      |
| `server/*`                 | Nitro 何时跑；与 `app/middleware/*` 的分工                  |
| `app/lib/http/*`           | 信封校验、401 重试一次、header 脱敏                         |
| `app/plugins/*.ts`         | universal / client；默认启用还是 env 守卫                   |
| `i18n/index.ts`            | 语言模块加载、切换 URL helper                               |
| `i18n/zh-CN                | en-US/index.ts`                                             | **仅文件头**；说明文案域划分；禁止逐 key 注释 |
| `tests/**/*.test.ts`       | 测什么、mock 什么、不覆盖什么                               |
| 纯 barrel `index.ts`       | 对外导出面列表；不必每个 export 行注释                      |
| `app/assets/styles/*.scss` | 与 `config/theme.ts` / tokens 的关系                        |
| `app/shims.d.ts`           | 类型声明用途（一行职责即可）                                |
| `docker/*`、根配置         | 与 Compose / 部署栈的关系                                   |

### 2.3 页面类 Vue 合并模板（迁移用）

现有 13 个 page 已用 `【定价页】+ UI 区块 / 用户流程 / 数据·API / SEO·边界` 格式。**不要整页推倒重写**，按以下合并：

1. 保留对理解 UI 有帮助的 **UI 区块、用户流程、子组件** 段落（可继续用 `【页面名】` 作标题）。
2. **补全或改写**为六字段：尤其【架构位置】【依赖关系】【边界与注意】。
3. **修正已知错误**（见第 11 节存量清单）。
4. API 描述允许两种写法（见 2.4）。

### 2.4 API 路径在注释里的写法

| 场景                                           | 写法示例                                                       |
| ---------------------------------------------- | -------------------------------------------------------------- |
| `app/api/*`、`features/*/api.ts` 文件头 / 行内 | 相对路径：`/projects`、`/documents/:id`（**不含**重复 `/api`） |
| page 文件头「数据·API」                        | 可写完整网关路径：`GET /api/content/pricing`（便于联调）       |
| 提及 `NUXT_PUBLIC_API_BASE`                    | 说明 base 已含 `/api` 前缀                                     |

### 2.5 易混淆文件：注释与 Prompt 中必须使用全路径

| 简称（禁止单独使用） | 全路径                                   |
| -------------------- | ---------------------------------------- |
| auth middleware      | `app/middleware/auth.ts`                 |
| auth API             | `app/api/auth.ts`                        |
| auth store           | `app/stores/auth.ts`                     |
| locale middleware    | `app/middleware/locale.global.ts`        |
| product canonical    | `server/middleware/product-canonical.ts` |

## 3. 关键代码注释标准

**必须注释**（读代码 10 秒内无法推断的逻辑）：

- `app/middleware/locale.global.ts`：尾斜杠、/zh 重定向、产品 URL 301、不支持语言 404
- `server/middleware/product-canonical.ts`：服务端最早的产品 URL 301（与 locale middleware 双层）
- `app/middleware/auth.ts`：`ensureSession`、登录 redirect、RBAC
- `app/api/auth.ts` → `refreshAccessTokenOnce`：401 单飞 refresh
- `app/api/clients.ts` → `createPublicApiClient`：剥离 authorization/cookie
- `app/features/editor/components/EditorWorkspace.vue`：`AUTOSAVE_DEBOUNCE_MS`、draft 首次非空保存、`onBeforeRouteLeave` flush
- `app/pages/docs/[id].vue`：`cachedProject` 防闪烁
- `app/composables/usePageSeo.ts` → `buildPageSeoLinks`：noindex 时不输出 hreflang
- `app/stores/auth.ts` → `logout()` vs UI 层 `router.push`
- `app/pages/[[language]]/sign-up.vue`：注册不自动登录
- `app/utils/attribution-params.ts`：last-touch 按 key 合并
- `app/plugins/analytics.client.ts`：启用需同步 CSP `script-src`
- `app/features/workspace/components/WorkspaceProjectCard.vue`：share/download/favorite 为 UI 占位

**禁止注释**：

- `// 导入 vue`、`// 定义变量`
- 与代码字面意思完全重复的说明

## 4. 项目架构约束（注释不得写错）

1. **公开区 vs 产品区**：公开页可 `/en` 前缀；产品 URL 语言中性（`/workspace`、`/docs/**`、`/account`）
2. **`PUBLIC_PAGE_PATHS`** 在 `config/site.ts`；`config/routes.ts` 通过 `publicLocalizedPaths()` 展开
3. **`/sign-in`、`/sign-up`**：noindex；**不在** `PUBLIC_PAGE_PATHS`；默认 **SSR**（非 prerender）
4. **三类 API client**：Public（剥 token）/ Auth / Product（401 单飞 refresh）
5. **`createProductApiClient`** 定义在 **`app/api/auth.ts`**，不在 `app/api/clients.ts`
6. **Feature 引用**：只从 `~/features/xxx` barrel 导入
7. **`authStore.logout()`** 不跳转；`AccountPage`、`UserAccountMenu` 在 `await logout()` 后 `router.push(localePath('/'))`
8. **注册** 不自动登录
9. **adapter 路径** 不含重复 `/api`
10. **渲染**：prerender（`/`, `/about`, `/help` 及 `/en` 变体）；SWR（`/news/**`, `/pricing`）；CSR（产品区）
11. **`WORKSPACE_NEW_PROJECT_ID = 'new'`** 对应 `/docs/new`；首次非空保存 `createWorkspaceProject` 后 `router.replace` 到 `/docs/:id`

## 6. 执行批次

**规则**：

- 每批完成后 **人工验收**，再进下一批。
- 批次 0 验收通过的文件，后续批次 **跳过或仅增量补全**，不重复重写。
- 每批结束运行：`pnpm lint && pnpm typecheck`（仅注释变更也应通过）。
- Git：**每批一个 commit**（message 如 `docs(comments): batch N - config/i18n/server`）。

| 批次   | 范围                                                                                                      | 重点                               |
| ------ | --------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| **0**  | `config/site.ts` + `app/middleware/locale.global.ts`                                                      | 定风格；更新第 12 节进度表         |
| **1**  | 其余 `config/` + `i18n/` + `server/`（**跳过** batch 0 已验收文件）                                       | 单一来源、SEO、sitemap、301        |
| **2**  | `app/lib/http/` + `app/api/` + `app/utils/` + `app/plugins/`                                              | 信封、三类 client、归因、analytics |
| **2b** | `app/middleware/auth.ts`（**跳过** batch 0 的 locale.global）                                             | auth 决策树、RBAC                  |
| **3**  | `app/stores/` + `app/composables/`                                                                        | auth 状态机、SEO、locale、theme    |
| **4a** | `app/layouts/` + `app/components/` + `app/assets/styles/`                                                 | shell、auto-import 组件、tokens    |
| **4b** | `app/pages/`（13 个，按 2.3 迁移）                                                                        | 页面薄/feature 厚；修正存量错误    |
| **5**  | `app/features/*`（6 个子批，见 6.1）                                                                      | shell → 业务 → api                 |
