# 通用基础版 Starter 优化计划

> 在保持现有架构（Feature-first、API 分层、混合渲染）的前提下，补一层**地域无关、低耦合、可配置**的基础能力，使 fork 出去的项目可直接扩展，而不绑定海外或国内某一套业务。

## 背景与输入来源

本计划由三部分合并而成：

1. **aippt-home 上线经验**（海外 AiPPT 营销站）：渠道归因、分析脚本延迟加载、Programmatic SEO、图片 LCP 优化等实战做法。
2. **nuxt-modern-starter 自身缺口**：缺统一 `pnpm quality` 发布门禁（远端 CI 可选）、SEO composable 可再增强、无归因/统计插件位、无图片性能范例。
3. **国内/海外讨论后的通用化**：UTM 泛化为「渠道归因参数」；Google/GTM 泛化为「analytics 插件位 + env」；不做地域分叉模板。

### 从 aippt-home 吸收的优点

| 计划项           | aippt-home 对应做法                                | Starter 取舍                                                          |
| ---------------- | -------------------------------------------------- | --------------------------------------------------------------------- |
| 渠道归因持久化   | `utils/utm-params.ts`：落地存参，注册/转化时再读   | 沿用 **localStorage**；策略改为 **按 key last-touch merge**（见 2.1） |
| 分析脚本延迟加载 | `hooks/use-ad-scripts.ts`：LCP + 首次交互后再注入  | v1 仅 **timeout defer**；LCP/交互检测放入 Backlog                     |
| SEO 增强         | templates 页完整 OG / Twitter / JSON-LD / hreflang | 集中 `usePageSeo`，Twitter/og:type 自动增强                           |
| BasePicture      | 首页 `<picture>` + webp + `fetchpriority`          | 组件 + 文档示例；首页 UI 不强制改                                     |

### 从 aippt-home 刻意避开的做法

| 不做法                                      | 原因                                                         |
| ------------------------------------------- | ------------------------------------------------------------ |
| 在 `nuxt.config app.head` 硬塞 GTM/广告脚本 | 拖慢 TTFB/LCP；aippt 自身也有 `useAdScripts` 被注释的反复    |
| 硬编码 GTM ID / OSS AccessKey               | 安全与可移植性差                                             |
| 每页手写 50+ 行 `useHead`                   | 重复高；Starter 应集中 `usePageSeo`                          |
| first-touch 归因（aippt 默认）              | Starter 选按 key last-touch merge，便于 SPA 内广告链更新渠道 |
| 14 语言 / SEM 全家桶 / 支付弹窗             | 业务域过重，不适合默认 Starter                               |

## 设计原则

1. **可选优于内置**：`webPage`、`includeOrganization`、`siteVerification`、analytics 默认关闭；Twitter / og:type / og:site_name 随 `usePageSeo` 自动增强，不算 opt-in。
2. **集中式 SEO**：公开页继续只调 `usePageSeo()`，不散落 `useHead`。
3. **客户端归因**：渠道参数仅在 client 读写 `localStorage`，不影响 SSR/prerender/SWR 缓存安全。
4. **最小 diff**：不调整目录大结构，不引入新的 heavy 依赖；**不建 `config/analytics.ts`**——analytics 默认值并入 `nuxt.config.ts`，归因常量与 storage key 放在 `app/utils/attribution-params.ts` 文件顶部。
5. **文档随功能**：同步更新 `docs/usage.md`、`docs/conventions.md`（Safety and Accessibility / CSP）；`config/content/faq.ts` 如有 SEO/归因描述则一并更新。

**title 解析规则（`buildPageSeoMeta` 必须遵守）**

`usePageSeo` 在调用 `buildPageSeoMeta` 前须先解析 **resolved title / description**（与现网 composable 行为一致）：

- **resolved title**：`input.title` 存在时为 `` `${input.title} · ${SITE_NAME}` ``，否则 `DEFAULT_SEO.title`
- **resolved description**：`input.description` → locale 默认文案 → `DEFAULT_SEO.description`
- **`og:title`、`twitter:title`**：均使用 **resolved title**（带 `· SITE_NAME` 后缀），不得用裸 `input.title`
- **`og:description`、`twitter:description`**：均使用 resolved description
- **`og:image`、`twitter:image`**：均使用 resolved 绝对 URL ogImage
- **article 页**：`og:type=article`；`article:published_time` 等 OG article 专用 meta 放入 Backlog（v1 仅 JSON-LD + `og:type`）

**Opt-in 增强（页面显式传参）**

| 参数                                            | 默认    | 行为                                                                                                                                                                                         |
| ----------------------------------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `webPage?: boolean`                             | `false` | 为 `true` 时输出 WebPage JSON-LD                                                                                                                                                             |
| `includeOrganization?: boolean`                 | `false` | 为 `true` 时输出 Organization JSON-LD（**仅首页传入**）                                                                                                                                      |
| `article?: { title, description, publishedAt }` | —       | 输出 Article JSON-LD；`og:type` 为 `article`                                                                                                                                                 |
| `siteVerification?: { baidu?, google? }`        | —       | **仅首页**传入；输出对应 `<meta name="...-site-verification">`；token 建议从 env / `runtimeConfig.public` 读取后传入，**勿硬编码进页面源码**（见配置约定 `NUXT_PUBLIC_*_SITE_VERIFICATION`） |

**`buildPageSeoScripts` 合并规则（必须遵守）**

```txt
1. 有 article           → 输出 Article JSON-LD（必须）
2. 有 article 且 webPage → 额外输出 WebPage JSON-LD（可选叠加）
3. 无 article 且 webPage → 仅输出 WebPage JSON-LD
4. includeOrganization   → 输出 Organization JSON-LD（与 1–3 可并存）
5. 以上皆无              → script 数组为空（与现网 noindex 产品页行为一致）
```

**JSON-LD 最小字段（`buildPageSeoScripts` 输出）**

| `@type`      | 必填字段                                                                            | 数据来源                                                                                                                 |
| ------------ | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Article      | `@context`, `@type`, `headline`, `description`, `datePublished`, `mainEntityOfPage` | `input.article` + canonical URL                                                                                          |
| WebPage      | `@context`, `@type`, `name`, `description`, `url`                                   | `input.title` / `input.description` + canonical URL                                                                      |
| Organization | `@context`, `@type`, `name`, `url`, `logo`                                          | `name` / `logo` 路径来自 `SITE_ORG`；`url` = `absoluteUrl(siteUrl, '/')`；`logo` = `absoluteUrl(siteUrl, SITE_ORG.logo)` |

**Organization 数据来源**

- `config/site.ts` 提供 `SITE_ORG = { name, logo }`（`logo` 默认 `/og-default.png`，与 OG 图共用）；**不在常量中写 `url`**。
- JSON-LD Organization 的 `url` 运行时取 `absoluteUrl(siteUrl, '/')`（站点根 canonical）；`logo` 取 `absoluteUrl(siteUrl, SITE_ORG.logo)`。
- 以上均使用 `runtimeConfig.public.siteUrl`，**不得**写死 `DEFAULT_SITE_URL`。

**类型分层（对外 API vs 纯函数入参）**

- **`PageSeoInput`**（对外，页面 / composable 唯一入口）：在现有字段基础上扩展 `webPage?`、`includeOrganization?`、`siteVerification?`；保留 `path`、`locale`、`title`、`description`、`ogImage`、`noindex`、`article`。
- **`PageSeoMetaInput` / `PageSeoScriptsInput`**（内部，仅供 `buildPageSeo*` 纯函数与单测）：由 `usePageSeo` 在运行时解析 `path`、`locale`、`runtimeConfig.public.siteUrl` 后组装，**不对外导出**。

```typescript
/** 页面调用 usePageSeo({ ... }) 时使用 */
type PageSeoInput = {
  path: string
  locale?: SupportedLocale
  title?: string
  description?: string
  ogImage?: string
  noindex?: boolean
  article?: { title: string; description: string; publishedAt: string }
  webPage?: boolean
  includeOrganization?: boolean
  siteVerification?: { baidu?: string; google?: string }
}

/** buildPageSeoMeta(input) — 内部纯函数入参（title/description 为已解析的 resolved 值） */
type PageSeoMetaInput = {
  siteUrl: string
  siteName: string
  title: string
  description: string
  canonical: string
  ogImage: string
  locale: SupportedLocale
  noindex?: boolean
  article?: PageSeoInput['article']
  siteVerification?: PageSeoInput['siteVerification']
}

/** buildPageSeoScripts(input) — 内部纯函数入参 */
type PageSeoScriptsInput = {
  siteUrl: string
  canonical: string
  title?: string
  description?: string
  article?: PageSeoInput['article']
  webPage?: boolean
  includeOrganization?: boolean
}
```

- **`usePageSeo` 实现约束**：解析 resolved title / description / canonical / ogImage 后，**必须**委托 `buildPageSeoLinks`、`buildPageSeoMeta`、`buildPageSeoScripts` 组装 `useHead` 的 `link` / `meta` / `script`；composable 内**不得**再内联 meta 或 JSON-LD 数组。`siteVerification` 由 `buildPageSeoMeta` 输出对应 `<meta name="google-site-verification">` / `<meta name="baidu-site-verification">`（token 非空时）。
- `buildPageSeoMeta`：`noindex` 页仍输出 Twitter / OG（与现网一致，仅 alternate 链接跳过）；`og:type` 有 `article` 时为 `article`，否则 `website`；`og:site_name` 取自 `siteName`（`SITE_NAME`）。
- `buildPageSeoScripts`：Article 抽取后字段须与现网内联 JSON-LD **完全一致**（含 `mainEntityOfPage` = canonical）；单测须做 refactor 回归断言。

**`nuxt.config.ts` siteVerification（迭代 1，并入 `runtimeConfig.public`）**

```typescript
googleSiteVerification: process.env.NUXT_PUBLIC_GOOGLE_SITE_VERIFICATION || '',
baiduSiteVerification: process.env.NUXT_PUBLIC_BAIDU_SITE_VERIFICATION || '',
```

首页从 `runtimeConfig.public` 读取后传入 `usePageSeo({ siteVerification: { ... } })`；**勿**在页面源码硬编码 token。

**API 示例**

```typescript

const runtimeConfig = useRuntimeConfig()
usePageSeo({
  path: '/',
  title: t('home.title'),
  description: t('home.lead'),
  webPage: true,

  siteVerification: {
    google: runtimeConfig.public.googleSiteVerification || undefined

// 定价页（自动 Twitter/OG；WebPage JSON-LD 为 fork 可选，v1 不修改 pricing.vue）

    title: article.title,
    description: article.description,
    publishedAt: article.publishedAt
  }
})
```

### 迭代 2：增长基础 + 体验（预计 3–4 天）

**目标**：渠道归因闭环；analytics 可插拔；图片组件文档化。

#### 2.1 通用渠道归因

**新增文件**

```txt
app/utils/attribution-params.ts   # 常量 + 纯函数（见下）
app/plugins/attribution.client.ts
tests/unit/attribution-params.test.ts
```

**修改文件**

- `app/stores/auth.ts`：在 **`logout()` 的 `finally` 中**（`reset()` 之前或之后）调用 `clearAttributionParams()`；**不得**在通用 `reset()` 内调用（见下「清理时机」）
- `app/apis/auth/index.ts`：在 `registerApi` 内对 body 执行 `mergeAttributionIntoBody`（见下）

**存储选型**

- 使用 **`localStorage`**（非 sessionStorage）：转化漏斗跨页面跳转更稳定（与 aippt-home 存储介质一致）。
- **策略为 last-touch merge（按 key）**（与 aippt first-touch 不同）：同 tab 内后续带参导航时，**仅覆盖本次 query 中出现的渠道 key**；未出现在新 query 中的旧 key **保留**（例如先落地 `/?utm_source=a&utm_medium=cpc`，再落地 `/?gclid=b` 时，storage 同时含 `utm_source`、`utm_medium`、`gclid`）。
- **注册成功后 storage 不清空**（body 已在 `registerApi` 发出）；**仅显式 `logout` 时** `clearAttributionParams()`，避免跨用户残留。登录转化未在 v1 示范，fork 须在 `loginApi` 内同样 merge（见 Out of Scope）。
- **共享设备未 logout**：用户 A 登录态下用户 B 在同一浏览器注册，会继承 A 落地时的渠道参数；fork 须按业务自行处理（例如注册前提示、登录成功后清空等）。Starter v1 仅保证 **`logout()` 清空**。

**清理时机（必须遵守，勿绑 `reset()`）**

`reset()` 会在 `ensureSession()`（refresh 失败、无 refreshToken）、`auth` store 内 `refresh()` 失败、`clearAuthSession()`（API 层 token refresh 失败）等场景执行。**匿名访客**无 token 时，`auth` 插件仅设 `status = 'unauthenticated'` 并 return，**不**调用 `reset()`。若把 `clearAttributionParams()` 放进 `reset()`，会与 `attribution.client.ts` 写入顺序冲突（插件默认按字母序：`analytics` → `attribution` → `auth`），在「有 token 但 session 失效」的首屏场景导致 UTM **写入后立即被清**。

| 场景                                                  | 是否清归因                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------- |
| 带 UTM 落地 / SPA 导航 / 整页刷新（未 logout）        | **保留**                                                            |
| token refresh 失败 → `reset()` / `clearAuthSession()` | **保留**（同设备继续注册仍应带上渠道）                              |
| 用户显式 **`logout()`**                               | **清空**（`finally` 内调 `clearAttributionParams()`，再 `reset()`） |

```typescript
const logout = async () => {
  try {
    if (accessToken.value) {
      await logoutApi(accessToken.value, refreshToken.value)
    }
  } finally {
    clearAttributionParams()
    reset()
  }
}
```

**常量位置（不建 `config/analytics.ts`）**

以下常量定义在 `app/utils/attribution-params.ts` 文件顶部：

```typescript
export const ATTRIBUTION_STORAGE_KEY = 'attribution_params'

/** 精确匹配或正则；任意命中即视为渠道参数 */
export const ATTRIBUTION_KEY_PATTERNS: Array<string | RegExp> = [
  /^utm_/,
  'bd_vid',
  'clickid',
  'gclid',
  'msclkid',
  'fbclid', // Meta
  'ttclid' // TikTok
]
```

更多平台参数（如 `_hsenc`、`li_fat_id`）由 fork 项目自行追加到该数组。

**API**

```typescript
/** 从 query 提取渠道 key；按 key last-touch：本次 query 中的 key 覆盖 storage 同 key；无渠道 key 时不写 storage */
saveAttributionParams(query: Record<string, unknown>): void

getAttributionParams(): Record<string, string>
clearAttributionParams(): void

/** 将已存归因字段浅合并进请求 body；SSR / 无 localStorage 时原样返回 body */
mergeAttributionIntoBody<T extends Record<string, unknown>>(body: T): T
```

**合并顺序（必须遵守）**

```typescript
// body 字段优先：同 key 冲突时以 body 为准（username / password 不被归因覆盖）
return { ...getAttributionParams(), ...body }
```

归因 key（`utm_*`、`gclid` 等）与 `username` / `password` 不会重叠；单测仍须覆盖「假设冲突时 body 优先」。

**query 值规范化**

- Vue Router 可能给出 `string | string[]`；写入 storage 前统一为字符串：**数组取第一个元素**，空数组忽略该 key。
- 非字符串值（`null` / `undefined` / 对象）忽略，不写入。

**识别与写入规则**

- 只要 query 中出现 `ATTRIBUTION_KEY_PATTERNS` 中任一 key（含单独 `?gclid=`、`?bd_vid=`），即触发 merge 写入。
- 不要求同时存在 `utm_source` / `utm_medium` / `utm_campaign`。

**插件行为（`attribution.client.ts`）**

Nuxt SSR 场景下，插件注册时初始导航可能已完成，**仅 `afterEach` 会漏掉首屏落地 query**。采用「首屏同步读 + `afterEach`」组合，共用同一捕获函数（写入幂等，不构成重复业务逻辑）：

```typescript
const captureFromQuery = (query: Record<string, unknown>) => saveAttributionParams(query)

export default defineNuxtPlugin((nuxtApp) => {
  const router = nuxtApp.$router
  captureFromQuery(router.currentRoute.value.query)
  router.afterEach((to) => captureFromQuery(to.query))
})
```

1. 插件初始化时读 **`router.currentRoute.value.query`**（覆盖首屏带参落地）。
2. **`router.afterEach`** 覆盖后续 SPA 跳转。
3. 仅 client 执行；不读 cookie、不碰 public SSR 请求。
4. `saveAttributionParams` 本身幂等：无渠道 key 时不修改 storage；若 `afterEach` 对首屏再次触发，同值写入无副作用。

**注册接入（Starter 范例，非强制后端字段）**

- 在 **`registerApi` 函数体内**（`app/apis/auth/index.ts`）对 `payload` 调用 `mergeAttributionIntoBody` 后再 `sendAuthApiRequest`。
- `getAttributionParams()` 在非浏览器环境返回 `{}`，无需额外 `import.meta.client` 判断。
- `RegisterPayload` 对外类型保持 `{ username, password }`；`registerApi` **内部** merge 后传给 `sendAuthApiRequest` 的 body 可断言为 `RegisterPayload & Record<string, string>`（或等价宽化），避免改动 store / 页面调用签名。
- **v1 仅示范注册转化**；登录转化需在 fork 项目的 `loginApi` 内同样调用 `mergeAttributionIntoBody`（见 Out of Scope）。
- **文档说明**：后端是否接收归因字段由 fork 项目 API 契约决定；Starter 只示范前端传递。

**v1 能力边界（写死，避免 scope creep）**

| 支持                                      | 不支持（Backlog / 文档手工步骤）                                          |
| ----------------------------------------- | ------------------------------------------------------------------------- |

|                                           | 硬编码任何平台 ID                                                         |

**`load-script.ts` 最小行为**

```typescript
/** 在 deferMs 后向 document.head 追加 <script src async>；已加载同 src 则跳过；onerror reject */
loadExternalScript(src: string, deferMs?: number): Promise<void>
```

- `deferMs` 非法或未传时 fallback 为 `3000`（与 `runtimeConfig` 一致）。
- CSP 拦截或网络失败时 Promise reject；插件内 catch 并 `console.warn`，**不抛未捕获异常**。

**插件 guard（`analytics.client.ts`，必须遵守）**

| 条件                              | 行为                                             |
| --------------------------------- | ------------------------------------------------ |
| `analyticsEnabled !== true`       | 静默跳过，无网络请求、无 warn                    |
| `analyticsScriptSrc` 为空或仅空白 | 静默跳过，无 warn（即使 enabled=true）           |
| 上述均满足且 `script-src` 已放宽  | 调用 `loadExternalScript(src, analyticsDeferMs)` |
| 同 `src` 已在 DOM 中              | `loadExternalScript` 内跳过重复注入              |
| 加载失败（CSP / 网络）            | `console.warn`，不抛未捕获异常                   |

**CSP 联动（必做，非可选文档）**

当前 CSP：

- `script-src 'self' 'unsafe-inline'` → **会拦截外部 analytics 脚本**（v1 主要卡点）
- `connect-src 'self' https: ...` → 已允许 HTTPS 上报，**通常无需为 GA 单独改 connect-src**

- 默认（analytics 关闭）：保持现有严格 CSP，验收「零额外请求」。
- 启用 analytics 时：在 `docs/usage.md` + `docs/conventions.md` 说明须将脚本域名加入 `script-src`，示例：

```txt
script-src 'self' 'unsafe-inline' https://www.googletagmanager.com;
```

- **不在 v1 自动改 CSP**（避免默认面放宽）；fork 项目按 env 自行调整 `nuxt.config.ts`。

| 风险                                        | 应对                                                                                                                                      |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 无 `public/` 目录                           | 迭代 1 先建目录再放 `og-default.png`                                                                                                      |

| 归因跨用户残留                              | **仅 `logout()`** 调 `clearAttributionParams()`；**禁止**绑在 `reset()` / `clearAuthSession()`（会与 `ensureSession` / refresh 失败冲突） |
| 共享设备未 logout 归因污染                  | 用户 B 可能继承用户 A 的渠道参数；文档说明限制；fork 按业务处理（注册前提示、登录后清空等）                                               |
| 匿名访客 auth 插件误清 UTM                  | 无 token 时插件不 `reset()`；验收含「带 UTM 落地 → 整页刷新 → storage 仍保留」                                                            |
| token refresh / `clearAuthSession` 误清归因 | refresh 失败只 `reset()` session，**不清** localStorage 归因                                                                              |
| localStorage 归因与 GDPR                    | Starter 不做 CMP；出海 fork 在启用归因 / analytics 前须接 cookie consent                                                                  |
| `pnpm quality` 耗时长                       | 含 build，约 2–5 分钟；仅发布 / 部署前跑，非每次 commit                                                                                   |
| 归因跨 tab 覆盖                             | last-touch 设计如此；Backlog 可提供 first-touch 或 tab 隔离策略                                                                           |
| 首屏落地 query 漏捕获                       | 插件须 `currentRoute` 同步读 + `afterEach`；验收含「无 SPA 跳转」用例                                                                     |
| 按 key merge 残留旧 utm                     | 文档写清语义；Backlog 可提供「新渠道参数整包替换」策略                                                                                    |
| 注册后 attribution 仍保留                   | 设计如此（转化已发出）；logout 清空；login merge 由 fork 自行接入                                                                         |
| analytics enabled 但 src 为空               | 插件静默跳过，不 warn                                                                                                                     |
| CI build / sitemap API                      | 依赖 fallback slugs；`pnpm quality` 与可选 workflow **无需 mock API**                                                                     |
| `usePageSeo` API 膨胀                       | JSON-LD / siteVerification 均 opt-in；Twitter/og:type/og:site_name 自动                                                                   |
| GTM 需 inline 脚本                          | v1 不支持完整 GTM 容器（不能仅靠 `SCRIPT_SRC`）；单文件 `gtag/js` 可接；Backlog Analytics v1.1 或文档手工接入                             |
| OG / logo 404                               | 迭代 1 必须补 `public/og-default.png`                                                                                                     |
| last-touch 与 aippt 不一致                  | 文档与单测写清**按 key merge** 语义；Backlog 可提供 first-touch 或整包替换开关                                                            |
| query 值为数组                              | 取首元素再写入；单测覆盖                                                                                                                  |
| `analyticsDeferMs` 非法 env                 | `Number.isFinite` 校验，fallback `3000`                                                                                                   |
| CSP 拦截 analytics 静默失败                 | manual 验证 Network + console warn；文档写清 script-src 改法                                                                              |
| Article JSON-LD refactor 回归               | 单测断言与 refactor 前 innerHTML 字段一致                                                                                                 |
| Twitter / OG title 不一致                   | `buildPageSeoMeta` 统一使用 resolved title（含 `· SITE_NAME`）                                                                            |
